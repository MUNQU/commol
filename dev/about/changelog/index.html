    Changelog¶

    Back to Home

    All notable changes to Commol will be documented in this file.

    The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

    [Unreleased]¶

    Added¶

    • ObservedDataPoint(scale=...): a known positive number, 1 by default, that multiplies the prediction of the observation, with its factor. A count model reads the mean scale · model, so a count observed on a known share of the model output stays whole. The loss, the likelihood, the predictive, the scores, the figures, the observed block of a report (scales) and a PredictionSpec(scale=...) of a prediction profile read it. See Observations.
    • ModelBuilder.add_matrix(id, stratification, values, unit, description) adds a matrix between the categories of a stratification, and a transition rate reads it with matrix_sum(M, e): in a compartment of category i, Σ_j M[i, j] · e_j, with each bin of e read as its amount in category j and total as the total of j. Every engine runs it. A rate or a formula parameter reads the entries as M_<i>_<j> and the spectral radius of the matrix as M_radius. The unit check, the equations and Model.describe read the matrix. See Matrix sums.
    • ModelBuilder.add_matrix(row_scales=..., column_scales=...): a constant or a parameter to calibrate multiplies the row or the column of a category, so the model reads diag(a) · values · diag(b). A calibration constraint reads M_<i>_<j> and M_radius of the scaled matrix at the values of each point, so a bound such as 2 - k * M_radius is one constraint; a rate reads them at the values of its run. See Constraints.
    • GibbsResult and ConformalResult give block_length and block_length_estimates, as the bootstraps, the jackknife and the sandwich do: the length a method ran with, and with block_length="auto" the estimate of each series, by label. GibbsResult gives them for InformationMatchingEta and BootstrapCoverageEta, and None for a number η; ConformalResult for JackknifePlus and EnbPI, and None for the variants without blocks. See Sequential Monte Carlo and Conformal Prediction Intervals.
    • ProfileIdentifiability(result=profiles) in commol.identifiability: the identifiability report of the verdicts of a ProfileResult, run through Calibrator.identifiability as every identifiability method. It runs no model, and it refuses the profiles of another problem with a ValueError that names the parameters of both. See Profile Likelihood.

    Changed¶

    • Breaking: Calibrator.delta_band(result, positions, confidence_level) is LocalResult.delta_band(calibrator, positions, confidence_level), a method of the result of Laplace and of Sandwich. DeltaBand is documented with commol.local. Migration: calibrator.delta_band(laplace, [10, 20], 0.9) is laplace.delta_band(calibrator, [10, 20], 0.9). See Local Approximations.

    • Breaking: ProfileResult.identifiability() is removed. Migration: profiles.identifiability() is calibrator.identifiability(ProfileIdentifiability(result=profiles)).

    • Breaking: each public name outside the main flow lives in the module of its page of the guide, and the root commol holds only the main flow: build (ModelBuilder, Model, StratificationCondition, StratifiedRate, SeriesValue, AxisUnits, AxisPattern), the structures (Aggregate, Complete, Groups), simulate (Simulation, InfeasibleStateError), calibrate (Calibrator, CalibrationProblem, CalibrationParameter, CalibrationConstraint, ObservedDataPoint, NelderMeadConfig, ParticleSwarmConfig, Quantile) and build_info. The modules are commol.engines, commol.plotting, commol.parallelism, commol.distributions, commol.quantities, commol.observations, commol.uncertainty, commol.scores, commol.resampling, commol.profiles, commol.local, commol.smc, commol.conformal, commol.identifiability and commol.sensitivity; the API Reference lists the names of each. The packages commol.api, commol.context and commol.utils and the module commol.constants are removed: the code is in the package of its module, and the code of the root in private packages. Migration: from commol import BayesianBootstrap, Predictive is from commol.resampling import BayesianBootstrap and from commol.uncertainty import Predictive; commol.threads(2) is commol.parallelism.threads(2).

    • Breaking: each module logs as commol.<module>, such as commol.resampling, and the main flow as commol; the loggers of the old paths, such as commol.api.calibrator, are gone. Migration: a handler or a level on commol still reaches every message; read one module with logging.getLogger("commol.resampling").
    • Breaking: a pickle of an object of commol 0.10 does not load: the path of each class changed. Migration: save a model with Model.to_json and a result with model_dump_json, which do not depend on the path.
    • Breaking: ParticleSwarmConfig is one class with plain fields, and its chained methods .inertia, .acceleration, .velocity, .mutation, .improvement_stop and .radius_stop and their *_config properties are removed, with the PSO* classes of commol.context.calibration and the PSO* enumerations of commol.context.constants. Each strategy is a name (inertia, acceleration, mutation, initialization), and its numbers are fields: inertia_factor, inertia_min, inertia_max, cognitive, social, cognitive_initial, cognitive_final, social_initial, social_final, mutation_scale, mutation_probability, mutation_application, velocity_clamp_factor, velocity_mutation_threshold, improvement_window, improvement_tol_abs, improvement_tol_rel and radius_tol. A number set without its strategy raises ValueError. Migration: ParticleSwarmConfig().inertia("chaotic", w_min=0.4, w_max=0.9).improvement_stop(window=30, tol_abs=1e-12, tol_rel=1e-9) is ParticleSwarmConfig(inertia="chaotic", inertia_min=0.4, inertia_max=0.9, improvement_window=30, improvement_tol_abs=1e-12, improvement_tol_rel=1e-9); c1_* is cognitive_*, c2_* is social_*, .velocity(clamp_factor=…, mutation_threshold=…) is velocity_clamp_factor=…, velocity_mutation_threshold=… and .radius_stop(tol) is radius_tol=tol. See Particle swarm.
    • Breaking: the members that converted an object to the engine are removed: Calibrator.rust_problem and rust_optimizer, rust_predictive, rust_observation_draws and rust_log_score of Calibrator and SensitivityAnalysis, SensitivityAnalysis.rust_analysis, rust_parameters and rust_prior of the distributions, Priors.rust_priors, InputSpace.rust_distributions, rust_json of the quantities and ParameterSample.rust_sample; the predictive members of a source are private. Migration: build a predictive with Predictive and score it with commol.scores, as before; the engine reads each object from the JSON of its model_dump().
    • Breaking: the tag of Complete and Groups in the JSON of a model is kind, in place of type. Migration: in a saved model, rename the key "type" of each neighbors entry to "kind".
    • Breaking: Model.describe() gives a graph of the strata, between the graph of the bins and the graph of the compartments, when the model moves amounts between categories, so ModelDescription.graphs() gives three graphs for such a model. A move between categories, also one by a stratified rate whose condition has to, is an edge between categories, not an edge from a bin to itself. The graphs of the bins and of the strata hold one edge per pair of nodes, labelled with the formula of its one rate or with the parameters that its rates read, and one node none for the inflows and one for the outflows; the label no longer starts with the id of the transition. The Markdown rendering draws both graphs. See The state graphs.
    • Each data object reaches the engine as the JSON of its model_dump(): the model, the calibration problem and each inference method, whole. A setting that the engine rejects raises ValueError with the path of its field before the message of the engine (optimization_config.inertia_factor: inertia_factor is a number greater than 0, got -1). NelderMeadConfig, ParticleSwarmConfig, the four bootstraps and the observation noises have a field kind with a default, the tag of their union. The engine fits the problem for each method that needs a fit, and calibrates η and the threshold of a profile. The results are the same for the same settings and seed.
    • An unknown name of an engine, a model kind, the levels of commol.set_threads, or the score or by of a conformal method gives the message of the reader of the engine, which lists the valid names, such as unknown variant `Stochastic`, expected one of `DifferenceEquations`, … or score: unknown variant `other`, expected one of `absolute`, `normalized`, `spread`. A conformal method without score or by gives missing field `score`.
    • The JSON of every result (model_dump_json) is standard JSON: a number that is not finite is the text "Infinity", "-Infinity" or "NaN", as at the port of the engine. Before, ParameterSample, SMCResult, JackknifeResult, ConformalResult, PredictionIntervals and SeriesIntervals wrote the bare Infinity and NaN, which a standard JSON reader rejects, and the other results wrote null, which did not load back. A result reads its JSON back equal, a NaN included, and a result that 0.10 saved with bare Infinity or NaN still loads.
    • A method that fits the problem before it runs (the bootstraps, the jackknife, the local approximations, the conformal methods, the profiles, and the Gibbs posterior with a calibration of η) no longer logs Starting calibration … at info level, since the engine runs that fit. A start of the fit that fails is still logged as a warning, and Calibrator.run still logs its start.
    • A formula has at most 100 000 nodes (numbers, variables, operators and calls), next to its limit of 100 levels of nesting: a longer one raises ValueError when its object is built, before it compiles. A message of the parser or of the compiler quotes the formula cut after its first 80 characters. See Limits of the parser.
    • A rate gives the same description with or without spaces: the description and its LaTeX are written from the tree that the parser of the engine reads, so k1*A*B/total and k1 * A * B / total give one description. A formula shows one space around each operator, only the parentheses that its grouping needs, ^ for a power and each number as its value (1e-5 shows as 1e-05, 2.0 as 2). In LaTeX, a power raises its exponent (A^{2}), % is \bmod and a comparison has its symbol (\leq). See The equations.
    • The unit check reads the tree of the engine: it reads ! in a condition and a variable named like a word of Python, such as lambda, and a formula outside the language gives the message of the parser.
    • Breaking: AxisUnits.rate_from_mean_span takes a required keyword keep, with no default: "survival" gives the rate of today, which keeps the exponential survival at every step (1 - exp(-1/n) on a per-step engine), and "mean" gives 1/n, whose mean residence is n steps on a per-step engine. A continuous engine gives 1/n with both. With keep="mean", a per-step engine rejects a span shorter than one step with ValueError. Migration: add keep="survival" to keep each rate as it is. Another value of keep raises ValueError with the message of the engine, unknown variant `median`, expected `survival` or `mean`. See Units of the axis.
    • Breaking: the package root exports only the names a user writes: 99 names, down from 147. A result is reached from the object that returns it, typed as the return of that member and documented on its page; it is not an import. The names that leave commol are the results (SimulationResults, SimulationReplicates, ReplicateRuns, CalibrationResult, CalibrationEvaluation, CalibrationHistory, StartSummary, ModelDescription, Process, BuildInfo, and the result of every uncertainty, identifiability and sensitivity method with its parts), the bases ModelStructure, InferenceMethod, UncertaintyMethod, IdentifiabilityMethod and SensitivityMethod, the union ObservationModel, and the functions sample, windowed_totals and ci_percentiles. Migration: remove the import and annotate with the class of its module, such as commol.api.results.SimulationResults, or with no annotation. See API Reference.
    • Breaking: a condition is a StratificationCondition and a stratified rate is a StratifiedRate, which the package root exports; ModelBuilder.add_stratification, ModelBuilder.add_transition and AxisPattern take them, not dicts, and ConditionDict and StratifiedRateDict are removed. A StratifiedRate checks its rate with the parser of the engine when it is built, with $compartment set to the name of a compartment, and keeps a number as its string. Migration: {"stratification": "group", "category": "g1"} is StratificationCondition(stratification="group", category="g1"), and {"conditions": [...], "rate": "k1"} is StratifiedRate(conditions=[...], rate="k1"). See Stratified rates.
    • Breaking: a choice among names is a string of a Literal, not an enum or an alias: CalibrationParameter.parameter_type is one of "parameter", "initial_condition", "factor" and "noise", CalibrationProblem.loss_function one of "sse", "rmse" and "mae", and the mode of AxisPattern.combine one of "sum", "max" and "min". commol.context.constants (CalibrationParameterType, LossFunction, OptimizationAlgorithm), CombineMode and AxisPattern.SUM, MAX and MIN are removed, with the aliases of strings of the signatures, such as DescriptionFormat and Pooling. Another value raises the ValidationError of pydantic, or ValueError for combine, which lists the values. Migration: write the string, such as mode="max" for mode=AxisPattern.MAX.
    • Breaking: SimulationResults.sample(ids, at) and SimulationResults.windowed_totals(ids, window, at=None) read the bins, the accumulators and the outputs of a run; Simulation.sample and Simulation.windowed_totals are removed. Results without a model read output names. Migration: simulation.windowed_totals(results, ["cum"], 7) is results.windowed_totals(["cum"], 7). See Windowed totals.
    • Breaking: the pydantic validators of the public classes are private: each name starts with _, such as CalibrationProblem._validate_loss_or_models.
    • Breaking: StructuralRank gives no structural verdict when the tolerance of the ODE solver, not the structure, may set the rank. With DifferentialEquations, a point whose rank is below the number of parameters is evaluated again at rtol / 100 and atol / 100 (no lower than 1e-14); a parameter whose verdict changes there, or that is not identifiable when a point cannot run there, has the verdict None, with a reason that names ODESolver.rtol and ODESolver.atol. Before, the rank lost to the tolerance read as non_identifiable or in_combination. A parameter that no observation reads stays non_identifiable when every point runs at the tighter tolerances. StructuralVerdict.verdict and the values of StructuralSection.verdicts can be None, and merge keeps the verdicts of the other reports; PointRank holds the accuracy of its runs and the tighter rank; StructuralSection holds the accuracy, the tighter accuracy, the generic rank there (tighter_generic_rank) and the points that could not run there (unchecked). In Rust, SimulationEngine::accuracy returns an Accuracy in place of output_accuracy and output_absolute_accuracy. Migration: read a None verdict as no verdict, and tighten ODESolver.rtol and ODESolver.atol until the rank stops changing. See When the solver tolerance sets the rank.
    • Breaking: StructuralRank and Collinearity leave out the noise parameters of the observation models (parameter_type="noise"), which no prediction reads. Before, the zero sensitivities of a noise parameter lowered the generic rank, made it non_identifiable, and made every other parameter poorly_determined, collinear with it; a merge then read conflicting. Now the rank counts only the other parameters, a noise parameter has the structural verdict None with a reason, collinearity gives it no practical verdict, and no parameter is collinear with it. StructuralSection.projections and verdicts, and CollinearitySection.sensitivity and pair_gamma, have no entry for a noise parameter; both sections name it in the new field left_out, with the reason, and IdentifiabilityReport.report() gives left_out after skipped. Collinearity(max_subset_size=...) is at most the number of parameters that are not noise parameters, Collinearity needs at least 2 of them, and a problem whose calibrated parameters are all noise parameters is a ValueError for both methods. Migration: read the verdict of a noise parameter from StartsIdentifiability, SampleIdentifiability or the profiles; read left_out for the parameters a section leaves out; lower a max_subset_size above the number of the other parameters. See Noise parameters.

    Removed¶

    • Breaking: commol.utils.security is removed, with SecurityConfig, SecurityError, validate_expression_security and the config= argument of AxisPattern.combine and AxisPattern.from_formula. The parser of the engine is the only check of a formula: a rate, a formula parameter, a calibration constraint or an axis pattern that it rejects raises ValueError with its message, and no setting changes its limits. Remove the config= argument, and catch ValueError instead of SecurityError. A formula of the language that the old text guards rejected is now valid: a name with letters outside ASCII (α * β), a name such as __import__, os or my_key, a number such as 1e400, nan as the name of a variable, and a formula of more than 1000 nodes, 10 000 characters or 10 levels of nesting, within the limits of the parser. The build still rejects a variable that the model does not define. See Limits of the parser.

    Fixed¶

    • A figure of a run, or of its replicates, logs one warning for each factor of its observations that calibration_result does not have, and counts the factor as 1. Before, it logged the warning once for each observation and each replicate. The cumulative figure of a Predictive raises the ValueError of its other figures for a factor that the problem does not have; before, it drew the observation as if the factor were 1.
    • A number that is not finite in a model or in the settings of an engine reached the engine as null. An infinite tolerance of ODESolver raised a message about the type of the setting, and an infinite parameter value failed when the model ran, with a message about a parameter index. Such a number now reaches the engine as its text, as every setting does: ODESolver(atol=float("inf")) raises atol is a finite number greater than 0, got inf, and the infinite parameter value is rejected when the engine is built, with the name of the parameter.
    • The flow of a proportional rate is the whole rate times its source, in the description and in the unit check: a rate k1 + k2 from B is (k1 + k2) * B; before, both read k1 + k2 * B, and the unit check of such a model failed. In LaTeX, a division followed by a product is a fraction times the product: the flow of a proportional rate a / b from B is \frac{a}{b} \cdot B, no longer \frac{a}{b \cdot B}.

    Documentation¶

    • Design principles: the structure, the rules of each unit and of the interface, and the proof that every part of the code follows. «Before you change code» of AGENTS.md links them. tests/suite/test_architecture.py fails when a crate of crates/ depends on PyO3 or on the bridge.
    • A numbered list of the documentation keeps its first number, and a line inside a paragraph that starts with a number and a period, such as 512., stays in its paragraph: the site reads lists with sane_lists.

    [0.10.2] - 2026-10-24¶

    This release makes the engine the one source of every rule: the range of each setting, the values of a model, the windows, the checks of a model and a calibration, and the language of formulas, which commol now reads with a parser of its own. A value that was valid stays valid, and an invalid one still raises ValueError when its object is built, but the messages are the engine's. Read the changes before you upgrade: seeded results change value, as every draw comes from one seed scheme in which neighbouring seeds share no replicate; a chain of powers groups from the right, so 2 ** 3 ** 2 is 512; BootstrapCoverageEta gives a slightly different η; a stratification fraction outside 0 to 1 is rejected; and two results are equal when their values, a NaN included, and their positions, seed and model are equal, so a run is no longer equal to a plain dict. See Building models and Uncertainty.

    Changed¶

    • The engine holds the range rule of every setting: a count, a share, a length, a scale, a tolerance, a bound of an optimizer, an observation, an observation model, an axis pattern, a distribution, a quantity of interest and the setting of an uncertainty, identifiability or sensitivity method. A value outside its range still raises ValueError when the object is built, and the same values are valid; the message is the engine's, and names the setting and its range: replicates is a whole number of at least 1, got 0, sd is a finite number greater than 0, got 0. A count gives one message for every value outside its range, a negative one included, also when a binding is called with no Python object in between, and for Simulation.replicates (count is a whole number of at least 1, got 0) and Calibrator.run (starts is a whole number of at least 1, got 0). A seed outside its range gives seed is a whole number from 0 to 18446744073709551615, got -1 in every function that takes one: Simulation.run, Simulation.run_at, Simulation.replicates, CalibrationProblem, SensitivityAnalysis and each binding.
    • The engine holds the rule of every value of a model and of every window. An initial amount, an impulse and the points of a series fail when their object (Aggregate, Transition, SeriesValue) is built or an amount is updated, as before, and the same values are valid; the message is the one the model compiler gives, which names the bin, the compartment or the transition: Bin 'B': initial amount is a finite number of at least 0, got -1, Transition 't': impulse period is a finite number greater than 0, got 0, a series has one point per position, got two at 2. The windows of windowed_totals, of reports, of figures and of AxisUnits.window_start, window_end, window_index and window_ends come from the engine, with its messages (window is a finite number greater than 0, got 0, index is a whole number of at least 0, got -1), and an observation or a quantity whose window starts before 0 gives the window 4 that ends at 3 starts before 0; an end is at least its window. A tick_every of a figure that is not a finite number greater than 0 raises ValueError.
    • A calibration, a sensitivity analysis or any other method that sets a model parameter raises ValueError when it is built if the parameter is a formula or a series parameter. The engine computes such a parameter at each step, so a value set on it was lost and the method fitted nothing. The message is the engine's, for this case and for a parameter the model does not have: Parameter 'k9' is not in the model; the parameters that can be set are k1, k2. Python keeps no copy of this check.
    • The four engines of the aggregate kind name themselves in their messages by the name of the engine: a position an engine does not report at gives The DifferenceEquations engine reports only at integer steps; 2.5 is not one, and an impulse or a series point between two steps names the DifferenceEquations engine or the StochasticSteps engine.
    • Predictive.at_observations and every method that reads a predictive at other observations raise ValueError for a position the engine rejects, with the message of the engine, as a calibration does. The bands, the automatic block lengths and their estimates keep their values: one Rust function of each computes them for every method.
    • The engine decides the practical verdicts of Collinearity and SampleIdentifiability and the two notes of a profile on its refits, and results read a position with the rule of an observation: the verdicts, reasons, notes and values stay. windowed_totals reads each window as a calibration reads a windowed observation, and it gives floats. A figure asked for a series that is neither an output nor a bin or accumulator raises KeyError with the message of Simulation.outputs_for, and a sum of outputs that the results do not hold gives one message, Missing output series in results, in a simulation, a report and a figure.
    • The engine checks a model, a calibration and the engine settings, and Python repeats none of its checks, so each mistake gets the message of the engine. A parameter named after an engine variable, a bin, a compartment or a subgroup total names each conflict and asks to rename the parameter. An observation of an output the model does not have names the output, the observation and the outputs: Invalid observed output name 'X' for observation 'series1' (available: A, B, C). A factor with a bound of 0 or below fails with Factor parameter 'f' must have positive bounds (got min=0, max=2). Collinearity checks max_subset_size when it runs, with max_subset_size must be from 2 to the number of parameters (3), got 9. The needs of a stochastic engine (replicates, seed and replicate_summary of a calibration; replicates and seed of a sensitivity analysis) keep their messages, which the engine now gives.
    • ODESolver and StochasticEventsSettings take their defaults from the engine and check themselves with the engine when they are built: StochasticEventsSettings(epsilon=1.5) gives epsilon is strictly between 0 and 1, got 1.5.     [0.6.1] - 2026-10-22¶

    This release fixes bugs of 0.6.0 and changes no API. A series point or an impulse that the engine cannot run now fails at ModelBuilder.build and Model.update_parameters, not at Simulation. Errors of a Predictive draw say what was not feasible. A PRCC analysis with a NaN value raises a ValueError and no longer runs forever. The quantities of a sensitivity analysis read a gain at its start and give different labels to close positions. A windowed series is plotted at the position of each observation, and a figure no longer changes the global style of matplotlib.

    Fixed¶

    • The default label of a quantity of interest wrote each position with 6 significant digits, so two positions close together gave one label and the analysis raised ValueError: Trajectory(outputs="A", positions=[1000000, 1000001]) gave "A at 1e+06" twice. The label now writes each position in full ("A at 1000000", "A at 1000001").
    • ModelBuilder.build and Model.update_parameters accepted a series point or an impulse position that the engine cannot run, such as a point or an impulse_at of 1.5 under DifferenceEquations or StochasticSteps, or a "pulse" point at 1.5 under any engine; the error came only at Simulation(model), as RuntimeError.     • Breaking: get_category_fraction, subgroup_population and get_conditioning_categories resolve category ids like calibration: a qualified id (sex:female) selects its stratification and a bare name that more than one stratification declares raises instead of silently using the first one. get_conditioning_categories returns qualified ids for shared names.
    • Bin and bin-prefix initial-condition ids, and the remainder, resolve from the engine's compartment labels instead of name prefixes, so a bin A no longer covers the compartments of a bin A_x.
    • The Rust engine expands bins and accumulators in one function; the equation printer and unit checker use it (expanded_outputs) instead of their own Python expansion. The Rust ModelTypes gains DifferentialEquations, so any model definition can be expanded; the difference engine rejects it.
    • Breaking: update_bin_fractions / update_initial_conditions apply the same rule as construction: the bin fractions must sum to 1.0 after the update.

    • Breaking (Rust): SimulationEngine requires compartment_labels(). CalibrationProblem::fix_auto_calculated_parameters and get_parameter_fix_info are removed; applied_parameter_values returns the clamped values the objective scored, which is what results now report.

    • Breaking: transitions are planned by the Rust engine from compartment labels (bin and categories) instead of compartment names, in one planner shared by the simulation and print_equations. The printed equations are therefore the simulated ones: a per-capita rate is shown multiplied by its source (gamma * I), a transition without flows shows (no flows), and the compact form lists the flows of each transition.

    • Breaking: building a model rejects a stratified rate whose category conditions match no source compartment (use to to route into a stratification the source does not carry), a transition with several sources and a per-capita rate, a category transition without exactly one source and one target, and a flow that ends in categories no compartment has. These used to be skipped without notice.
    • Constraint aggregates (a bin or bin prefix in a constraint expression) are built from output labels, so a bin A no longer sums the outputs of a bin A_x.

    Fixed¶

    • A transition between bins no longer moves bins whose id starts with the source bin id: A -> B moved AB -> BB as well.
    • Transitions between the categories of a stratification (young -> old) are now simulated; the engine used to ignore them while print_equations showed them.

    • A transition with several sources or targets (A + B -> 2 C) now applies its flow to every source and target, as documented; the engine used to move only the first source to the first target.

    • The applied-parameters report now shows the effective head count for bin, stratification-category, and subgroup rows — the uniform expansion plus the declared compartment_fractions overrides — and reports each fraction as that head count over the declared population_size, so every row shares one denominator with N. An aggregate row written back as overrides no longer reports the stale pre-calibration value as calibrated, and a bin left uncalibrated keeps its null marker even when overrides touch some of its compartments.

    • A conditional-stratification category is calibrated as a fraction of its conditioning subgroup but reported as a fraction of the whole population, so the report rescales its interval by the subgroup's share of the population; the interval now brackets the reported fraction.
    • apply_calibration_parameters writes initial-condition values back so the model rebuilds the initial population the engine scored for them. Bin and category values update the fractions they declare, as the engine applied them; every compartment those fractions do not reproduce is pinned as a per-compartment override. The call computes the result before it changes the model, so a rejected value leaves the model unchanged.
    • population_size must be greater than zero, reported as a domain ValueError rather than a later ZeroDivisionError. update_bin_fractions re-applies the sum-to-1/conservation rule.
    • Calibrating a bare category name that two stratifications declare no longer builds an initial population larger than population_size: the engine used to split the overlapping pairs of both stratifications from one snapshot.
    • The PyO3 InitialConditions binding exposes population_size, bin_fractions, stratification_fractions and compartment_fractions with getters, and the _commol_rs stub declares only those real attributes (correcting the bin_fractions field name).
    • An initial-condition override that names an unknown compartment raises a ValueError when the model is built or updated, and a RuntimeError from the DifferenceEquations engine constructor.
    • The greedy ensemble search of probabilistic calibration takes its random starts from the shuffled part of the sample (argmin fork). The starts were biased towards low indices, so the same seed can now select a different ensemble.
